# 릴리스·호환성 정보

버전 체계와 컴포넌트 간 호환성 정보를 정리한다 — **틀만 구성**. 세 컴포넌트
모두 첫 정식 버전(`v0.0.1`) 태깅 완료, 이후 실제 이력이 쌓이는 대로 채운다.

---

## 1. 버전 체계

이미지는 `ghcr.io/cnapcloud/<컴포넌트>:vMAJOR.MINOR.PATCH` 형식으로 태깅된다
(semver). 컴포넌트(rag-api / rag-ent-api / rag-admin)는 각자 독립된 저장소·버전으로
릴리스되며, 태그는 자동 증가 없이 릴리스 시점에 사람이 직접 생성한다. `git tag`가 CI(테스트
+ 린트 + 타입체크)를 통과해야만 해당 태그의 이미지가 존재하므로, "이 버전이 존재한다 = 이
버전이 CI를 통과했다"가 보장된다. 자세한 절차는
[Runbook §A.4](../deploy/runbook.md#a4-업그레이드롤백)를 참조.

## 2. 컴포넌트 호환 매트릭스

컴포넌트별 최신 버전과, 그 버전이 요구하는 다른 컴포넌트의 최소 버전을 기록한다. 명시되지
않은 조합은 검증되지 않은 것으로 간주한다.

| rag-ent-api | 요구 rag-api | 요구 rag-admin | 비고 |
|-------------|-------------|----------------|------|
| `v0.0.1` | `v0.0.1` | `v0.0.1` | 세 컴포넌트 최초 태그, 같은 시점에 함께 검증 |

| 컴포넌트 | 버전 | 비고 |
|----------|------|------|
| rag-api | `v0.0.1` | 첫 정식 태그 (2026-07-10) |
| rag-ent-api | `v0.0.1` | 첫 정식 태그 (2026-07-10)  |
| rag-admin | `v0.0.1` | 첫 정식 태그 (2026-07-10) |

## 3. 마이그레이션 노트

버전 업그레이드 시 수동 조치가 필요한 항목을 버전별로 기록한다 (스키마 변경, 설정 필드
변경/삭제, 필수 환경변수 추가 등). 항목이 없는 버전은 별도 조치 없이 이미지 교체만으로
업그레이드 가능하다.

| 버전 | 필요 조치 |
|------|-----------|
| `v0.0.1` | 없음 (최초 버전) |
