# 제품 소개

## 개요

**RAG Platform은 사내 문서를 자동으로 수집·인덱싱하고, LLM 애플리케이션과 AI 에이전트에 고품질 하이브리드
검색을 공급하는 셀프호스티드 RAG 검색 플랫폼이다**

이 제품은 챗봇이나 앱을 만들어주는 도구가 아니다. 조직의 문서 지식을 "검색 가능한 상태"로
유지하고, 그 검색 능력을 REST API와 MCP(Model Context Protocol)로 어떤 LLM
애플리케이션에든 꽂아 쓸 수 있게 하는 **검색 백엔드(retrieval backend / context layer)**다.

핵심 가치 제안:

- **완전한 셀프호스팅** — 문서, 벡터, 메타데이터가 전부 고객 인프라 안에 남는다. 외부 SaaS
  의존 없이 온프레미스/프라이빗 클라우드에서 동작한다.
- **엔터프라이즈 접근제어** — 지식베이스(KB) 단위의 역할 기반 접근제어(RBAC)와 기업 SSO
  (OIDC/Keycloak)를 기본 제공한다. "누가 어떤 문서를 검색할 수 있는가"를 제품 수준에서
  통제한다.
- **한국어 문서 환경 특화** — HWP 포맷 지원, 한국어 형태소 분석(Kiwi) 기반 키워드 검색과
  중복 감지, 다국어 임베딩 모델(bge-m3)을 기본 구성으로 제공한다.
- **에이전트 시대 대응** — 검색·KB 조회 기능을 MCP 서버로 노출한다. Claude, IDE 에이전트 등
  MCP 클라이언트가 조직 지식에 접근할 때도 동일한 인증·권한 규칙이 적용된다.

## 대상 고객

| 세그먼트 | 특징 | 이 제품을 선택하는 이유 |
|----------|------|------------------------|
| 사내 AI 플랫폼 팀 | LibreChat, 자체 챗 UI 등 LLM 앱을 이미 운영, 검색 품질과 권한 관리가 과제 | 앱은 그대로 두고 검색 백엔드만 교체·강화. KB 단위 권한으로 부서별 지식 격리 |
| 보안·규제 민감 조직 (금융, 공공, 제조) | 문서를 외부 SaaS에 올릴 수 없음, 폐쇄망 요건 | 완전 셀프호스팅 + 로컬 임베딩으로 데이터 반출 제로 |
| 한국어 문서 중심 기업 | HWP·한국어 위키·규정 문서가 지식의 대부분 | HWP 파싱, 한국어 형태소 기반 검색·중복제거가 기본 동작 |
| 개발 조직 | Confluence·GitHub에 지식이 흩어져 있음 | 커넥터로 자동 수집·증분 동기화, 소스코드 AST 단위 청킹, IDE 에이전트에 MCP로 연결 |

## 사용 시나리오

### 부서별 지식베이스를 갖춘 사내 통합 검색

인사팀·법무팀·개발팀이 각자 KB를 만들고 소유자가 멤버를 초대한다. 직원은 자기가 권한을 가진
KB만 검색된다. 관리 콘솔에서 문서 업로드부터 인덱싱 상태 확인, 검색 테스트까지 처리한다.

### 기존 LLM 챗 서비스의 RAG 백엔드

LibreChat 등 챗 UI가 사용자의 SSO 토큰을 그대로 실어 `/api/search`를 호출한다. 서버가
호출자의 KB 권한을 확인해 접근 가능한 KB에서만 검색하므로, 챗 서비스 쪽에 권한 로직을 만들
필요가 없다.

### AI 에이전트의 조직 지식 접근 (MCP)

개발자가 IDE(VS Code, Claude Code 등)에 MCP 서버를 등록하면, 코딩 에이전트가 사내 아키텍처
문서·운영 가이드를 검색해 답한다. Enterprise 배포에서는 MCP 경로에도 동일한 JWT 인증과 KB
권한이 적용된다.

### 문서 소스 자동 동기화

Confluence 스페이스, GitHub 저장소, 사내 웹 포털을 커넥터로 등록하고 cron 스케줄을 걸어두면
변경분만 자동 재인덱싱된다. 페이지 첨부파일, 소스코드까지 수집 대상이며, 실패한 문서는 관리
콘솔에서 원인 확인 후 개별 재처리한다.

## 제품 구성

RAG Platform은 세 가지 컴포넌트로 구성된다.

| 계층 | 컴포넌트 | 역할 |
|------|----------|------|
| 코어 엔진 | rag-api | 문서 인제스트 파이프라인(파싱-청킹-임베딩-업서트), 하이브리드 검색, 커넥터, MCP 서버. 단독 배포 가능 |
| 엔터프라이즈 레이어 | rag-ent-api | rag-api를 라이브러리로 확장. OIDC 인증, KB 단위 RBAC, 멤버십·이메일 초대, 소유권 관리, 권한이 적용된 검색/MCP |
| 관리 콘솔 | rag-admin | 단일 빌드 웹 UI. KB/문서/커넥터 관리, 검색 콘솔, 인프라 상태 대시보드. 엔터프라이즈 배포에서는 SSO 로그인과 접근권한 관리 화면 활성화 |

두 가지 배포 형태를 하나의 코드베이스로 지원한다.

- **Core 배포**: rag-api + rag-admin. 인증 없는 내부망 전용 구성. 소규모 팀, PoC에 적합.
- **Enterprise 배포**: rag-ent-api + rag-admin(ENT 모드) + Keycloak 연동. 전사 서비스,
  부서별 지식 격리가 필요한 조직에 적합.

### 인프라 스택

Qdrant(벡터 검색), PostgreSQL(메타데이터), Redis(이벤트 큐), MinIO(원본 스토리지),
Dagster(파이프라인 오케스트레이션), Ollama 또는 OpenAI(임베딩)로 구성되며 모두 셀프호스팅
가능하다. 임베딩까지 로컬 모델(Ollama)로 구성하면 **외부 API 호출이 전혀 없는 완전 폐쇄망
운영**이 가능하다 (리랭킹은 선택 기능으로, 사용 시 Jina API 연동 또는 비활성화). 컴포넌트별
역할과 통신 구조는 [아키텍처](03-architecture.md)를 참고한다.

## 제품 포지셔닝

```
                앱/워크플로 빌더 지향
                        |
        Dify ●          |
                        |     ● RAGFlow (RAG+에이전트 통합)
  --------------------- + ----------------------
  범용/글로벌              |           특화/엔터프라이즈
                        |
      R2R ●             |   ● RAG Platform
     (API-first         |     (검색 백엔드 특화,
       RAG 엔진, MIT)    |      KB RBAC, 한국어, MCP)
       검색 인프라 지향
```

- Dify가 "LLM 앱을 만드는 플랫폼", RAGFlow가 "문서 이해가 강한 RAG+에이전트 엔진"이라면,
  RAG Platform은 **"기존/신규 LLM 앱과 에이전트에 검색을 공급하는 인프라"**다.
- R2R(SciPhi)은 같은 "검색 인프라 지향" 축의 아키텍처상 가장 가까운 비교 대상이며, 세 가지
  지점에서 접근이 다르다:
  - **엔터프라이즈 배포**: KB 단위 RBAC·SSO·한국어 특화를 갖춘 완결형 제품 — R2R은 범용
    오픈소스 컴포넌트(MIT)
  - **완전 셀프호스팅**: 표 인식(RapidTable)·스캔 OCR(RapidOCR)·표 위치 탐지(RapidLayout)
    전부 로컬 ONNX 추론, 실제 문서 셀 단위 정확도 검증 완료 — R2R의 프로덕션 권장 경로
    (`unstructured_api`)는 외부 SaaS 호출을 포함한다
  - **관리 UI**: KB/문서/커넥터 관리, SSO 로그인, 인프라 상태 대시보드까지 포함 — R2R
    공식 대시보드는 문서 업로드·플레이그라운드·로그 조회 수준이다
- 앱 빌더·챗 UI를 내장하지 않는 것은 의도된 비범위다. 그 자리는 LibreChat, 고객 자체 앱,
  MCP 클라이언트가 채우고, 본 제품은 그 아래에서 권한이 통제된 고품질 검색을 담당한다.
