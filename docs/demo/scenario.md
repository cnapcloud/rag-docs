# 데모 시나리오

[데모 영상](video.md)에서 실제로 확인할 수 있는 두 가지 시점 — 관리자(jane)와 초대받은
일반 멤버(john) — 을 통해 RAG Platform의 핵심 기능이 어떻게 동작하는지 정리한다. 모든
화면은 실제 rag-admin 콘솔이며, 나레이션이 아니라 실제 로그인·클릭으로 보여준다.

## 관리자(jane) 시점

- **Home** — 인프라 상태를 한눈에 확인
- **Knowledge Bases** — KB 목록과 상세 정보 확인
- **Connectors** — 나무위키 커넥터 설정 확인 및 수동 동기화 실행
- **Documents** — KB별로 인제스트된 문서 목록을 필터링하고, 특정 문서를 검색해 원본
  소스까지 확인
- **Query Playground** — 하이브리드 검색으로 자연어 질의("최고령 고양이 찾아줘")를 던지면
  관련 문서 스니펫이 근거로 함께 반환되는 것을 확인
- **Access Management** — 다른 KB(kb-02)에 신규 사용자(john)를 멤버로 초대 — 실제 초대
  메일 발송까지 확인

## 초대받은 멤버(john) 시점

- 로그인 직후 Knowledge Bases 목록에 **초대받은 KB(kb-02)만 보이는 것**을 확인 — KB 단위
  접근 제어가 실제로 격리되어 있음을 보여준다
- 스스로 새 KB(kb-04)를 만들고 문서를 업로드
- 업로드한 문서가 `running` 상태로 인제스트 파이프라인에 들어가는 것을 확인
- Dagster에서 방금 올린 문서의 파이프라인 실행(run)이 잡히는 것을 확인 — 업로드부터 실제
  처리까지 이어지는 흐름을 보여준다

## 확인되는 기능

| 기능 | 확인 지점 |
|------|-----------|
| KB 단위 접근 제어 | john 로그인 시 kb-02만 보임 (kb-01/03은 안 보임) |
| 멤버십 초대 | jane의 초대 → 실제 이메일 발송 → john 첫 로그인 시 자동 활성화 |
| 하이브리드 검색 | Query Playground의 자연어 질의 → 근거 문서 스니펫 반환 |
| 커넥터 동기화 | 나무위키 커넥터 수동 Sync |
| 인제스트 파이프라인 | 업로드 → `running` 상태 → Dagster run 이력 |

기능 자체에 대한 자세한 설명은 [Features](../overview/features.md)를 참고한다.
